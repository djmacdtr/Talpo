# 2026-09-18：Gate 0 本地 Worker 适配测试

## 目标

在隔离 fixture 中验证 Codex CLI + Ollama + 本地 GLM 能否完成“读任务、改文件、运行测试、输出 JSONL”的最小闭环。

## 环境

- Windows PowerShell
- Codex CLI `0.155.0-alpha.9`
- Ollama `0.34.2`
- Python `3.12.7`
- 本地模型：`glm-4.7-flash:q4_K_M`
- Codex 参数：`--oss --local-provider ollama --json --sandbox workspace-write --ephemeral`

## Fixture

`.gate0-fixture/task.md` 要求创建 `calculator.py` 的 `add(a, b)`，且不得修改 `test_calculator.py`，然后运行 `python -m pytest -q`。

## 实际结果

### 第一次尝试：未显式指定模型

- Codex 尝试拉取 `gpt-oss:20b`，下载大小约 12.85GB。
- 该模型不是本次目标，下载在接近 0.1% 时中止。
- Fixture 未被修改。

### 第二次尝试：显式指定 GLM

- Ollama 成功加载 `glm-4.7-flash:q4_K_M`。
- `ollama ps` 显示约 `69%/31% CPU/GPU`，上下文 `16384`。
- Codex 输出了 `thread.started` 和错误事件，但反复报告：
  - Ollama 模型列表响应缺少 Codex 期望的 `models` 字段。
  - 当前模型没有 Codex 内置 metadata，只能使用 fallback metadata。
  - `disable_response_storage` 是当前 Codex 不认识的旧配置项。
- 在有限等待窗口内没有产生 `command_execution`、`turn.completed` 或最终结果事件。
- 为避免继续占用本地推理资源，停止了本次 Codex 进程。
- Fixture 仍未生成 `calculator.py`，测试未执行。

## 结论

Gate 0 当前状态：`BLOCKED`。

这不是 GLM 文件缺失，也不是测试代码失败，而是 Codex OSS/Ollama 适配协议尚未在当前版本组合下跑通。Talpo 必须把 Worker 适配器、模型名映射、模型列表兼容、超时和取消作为 P0 能力，不能直接假设 `codex exec --oss` 就能接入任意 Ollama 模型。
